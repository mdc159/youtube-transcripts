# Human Tutorial Style Guide

Transform a YouTube tutorial into a clear, step-by-step guide optimized for a human developer or builder who wants to follow along and apply the knowledge to their own project.

## Output Format

### 1. Introduction
One or two paragraphs explaining what this tutorial covers, what the reader will achieve by the end, and why this approach is useful.

### 2. Prerequisites
A list of everything the reader needs before starting (tools, software, accounts, prior knowledge). Include versions if mentioned.

### 3. Core Concepts
Briefly explain the main ideas or technologies used in the tutorial. Focus on *why* they are being used.

### 4. Step-by-Step Instructions
Break the tutorial down into logical, numbered steps. For each step:
- **Goal**: What this step achieves.
- **Action**: Clear instructions on what to do.
- **Commands/Code**: Any code snippets or terminal commands required (use code blocks).
- **Explanation**: A brief explanation of *why* we are doing this or how the code works.

### 5. Tips and Gotchas
A bulleted list of common pitfalls, alternative approaches, or useful tips mentioned by the speaker. 

### 6. Conclusion
A brief wrap-up of what was accomplished and any recommended next steps or resources for further learning.

### 7. Open Questions
Anything the tutorial glossed over that the reader would need to figure out themselves. Always include this section; write "None identified" if the tutorial is complete.

---

## Rules

**Tone and Style:**
- Write in a conversational, encouraging, and clear tone, suitable for a human reader.
- Address the reader directly (e.g., "First, you'll need to...").
- Avoid overly robotic or terse formatting.

**Content Extraction:**
- Ensure all essential code snippets, commands, and configurations are captured accurately.
- Translate visual actions (like navigating a UI) into clear text instructions.
- Preserve the speaker's insights, tips, and warnings.
- Remove filler words, repetitive phrasing, and promotional content.
- If the speaker skips a small but obvious step (like saving a file), you may implicitly include it for clarity, but do not invent complex unstated commands.
